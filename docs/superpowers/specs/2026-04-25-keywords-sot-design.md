# Keywords Single Source of Truth

**Date:** 2026-04-25
**Status:** Approved

## Problem

Keywords, tags, and wikilinks describe the same concept but are stored in different places with different semantics. There is no unified single source of truth, making the system inconsistent and hard to manage. Additionally:
- Auto-discovery runs on a timer with no manual UI trigger
- The discovery activity panel is low-visibility at the bottom of the page
- Manual ingestion has no human-in-the-loop for keyword creation

## Design

### Core Concept

One concept, one name, one file. Every "keyword" is:
- A line in `_keywords` (the canonical master list in the vault root)
- A `keywords` entry in note frontmatter
- A `[[keyword]]` wikilink in note bodies

There are no "tags" as a separate concept. The `keywords` frontmatter field IS the tag system. The `[[wikilinks]]` IS the graph connectivity. Both derive from the same `_keywords` source.

### Rules

- **Only humans add keywords** — via manual ingestion prompts in the UI
- **Auto-discovery** — searches with existing keywords, saves notes with those keywords as `keywords` frontmatter and `[[wikilinks]]`, but NEVER creates new keywords
- **Delete keyword = cascade delete** — removing a keyword removes it from all affected notes; notes with no remaining keywords are deleted entirely

## Two-Phase Manual Ingest

### Flow

```
User submits URL/file in UI
        │
        ▼
Phase 1: POST /ingest/preview
  ├── Fetch/extract content (fast, lightweight)
  ├── LLM extracts 3-5 candidate keywords from content
  ├── Check each against _keywords master list
  ├── Return { existing: ["kw1"], new: ["kw2", "kw3"] }
        │
        ▼
  UI renders: keyword chips, existing ones dimmed/green, new ones highlighted blue
  User toggles which new keywords to accept
  User clicks "Confirm & Save" or "Cancel"
        │
        ▼
Phase 2: POST /ingest/run { url, accepted_keywords, source_type, ... }
  ├── Add any truly new keywords to _keywords file
  ├── Run full pipeline (enrich, similar, write note, index)
  ├── Note saved with keywords=accepted_keywords in frontmatter
  ├── Note body includes [[keyword]] wikilinks section
  └── SSE stream shows progress
```

### API

**`POST /ingest/preview`**
- Body: `url` or `file` (same as current ingest)
- Returns: `{ preview_id, keywords: { existing: [...], new: [...] }, title, snippet }`
- Fast: fetch + LLM keyword extraction only, no full pipeline
- No SSE, no job tracking

**`POST /ingest/run`**
- Body: `{ preview_id, accepted_keywords: [...] }`
- Returns: `{ job_id }`
- SSE stream at `/stream/{job_id}` for progress
- Runs full `run_pipeline` with accepted_keywords passed through

### Pipeline Changes

`run_pipeline()` gains a `keywords: list[str] | None` parameter:
- Set on the note dict before writing
- Passed to `write_note()` which writes `keywords` frontmatter and injects `[[wikilink]]` references in body
- If `is_discovery=True`, keywords come from the scheduler's keyword list (source_keyword + related)

### UI Changes (Ingest)

- After Phase 1 response, progress card shows extracted keywords with visual distinction:
  - Existing: green checkmark, disabled toggle
  - New: blue highlight, toggle on by default
- "Confirm & Save" button starts Phase 2
- "Cancel" button aborts
- Phase 2 uses the same SSE streaming as current ingest

## Note File Format

### Frontmatter

```yaml
---
title: Monish Pabrai on Charlie Munger Mental Models
source: https://www.youtube.com/watch?v=...
keywords: [mental-models, charlie-munger, decision-making]
ingested: 2026-04-25
type: video
---
```

### Body

The body includes a `## Keywords` section with wikilinks:

```markdown
## Keywords
[[mental-models]] · [[charlie-munger]] · [[decision-making]]
```

This section is auto-generated by `write_note()` when keywords are provided. It appears right after the summary, before content-specific sections.

### Migration

Existing notes with `tags` frontmatter need a one-time migration to `keywords`. The migration script:
1. Reads each `.md` in the vault
2. Renames `tags` frontmatter to `keywords`
3. Adds a `## Keywords` section with `[[tag]]` wikilinks

Existing `_keywords` entries that don't appear in any note's tags are preserved (they're active search keywords).

## Keyword Deletion

### Module: KeywordsManager (cascade delete update)

**Responsibility:** Remove keyword from `_keywords`, cascade delete affected notes, strip wikilinks from survivors.

**Interface:** `remove_keyword(keyword, _keywords_path, vault_path) → { deleted_files: [...], affected_files: [...] }`

**Dependencies:** `frontmatter` library, vector store

**Size target:** 200 lines

### Logic

1. Remove keyword line from `_keywords` file
2. Scan every `.md` in vault:
   - Parse frontmatter to read `keywords` list
   - If keyword NOT in `keywords` → skip file
   - If keyword IS in `keywords` AND `len(keywords) > 1`:
     - Remove keyword from `keywords` list in frontmatter
     - Strip `[[keyword]]` wikilinks from body
     - Rewrite file
   - If keyword IS in `keywords` AND `len(keywords) == 1`:
     - Delete file entirely
     - Remove from vector store
3. Strip any remaining `[[keyword]]` wikilinks from survivor files (belt-and-suspenders)

## UI Layout

### Order (top to bottom)

1. **Header** — unchanged
2. **Ingest Card** — two-phase flow (form → keyword preview → confirm → progress)
3. **Discovery Panel** — moved up from bottom to directly below ingest
   - Header: "Discovery" with "Run Discovery Now" button + refresh button
   - Stats row: discovered today count, queue depth, last cycle time
   - Activity feed: scrollable list of recent discovery events
4. **Two-column grid** — Keywords card + Recent Jobs card

### Discovery Panel API

**`POST /discovery/trigger`**
- Triggers one async discovery cycle
- Returns `{ cycle_id }` (204 accepted)
- Cycle progress recorded in discovery logger, visible on next panel refresh

**`GET /api/discovery/activity`** — unchanged, returns today's stats + events

## Module Design Blocks

### Module: `core/keyword_extractor.py`
- **Responsibility:** Extract candidate keywords from raw text using MiniMax LLM. Check each against `_keywords` and classify as existing vs new.
- **Interface:** `extract_and_classify(text, title, _keywords_path) → { existing: [...], new: [...] }`
- **Dependencies:** MiniMax API, `keywords_manager.load_manual_keywords`
- **Size target:** 80 lines (modify existing, currently 55 lines)

### Module: `app.py`
- **Responsibility:** HTTP API for two-phase ingest, discovery trigger, keyword CRUD.
- **Interface:** FastAPI routes: `POST /ingest/preview`, `POST /ingest/run`, `POST /discovery/trigger`
- **Dependencies:** pipeline, keyword_extractor, discovery_scheduler
- **Size target:** 280 lines (currently 203 lines)

### Module: `vault/writer.py`
- **Responsibility:** Write note with `keywords` frontmatter and `[[wikilink]]` references in body.
- **Interface:** `write_note(note, source, keywords, ...) → path`
- **Dependencies:** frontmatter library, config
- **Size target:** 350 lines (currently 329 lines)

### Module: `core/keywords_manager.py`
- **Responsibility:** CRUD for `_keywords` file + cascade delete of notes.
- **Interface:** `load_manual_keywords`, `save_manual_keywords`, `add_keyword`, `remove_keyword`, `purge_keyword`
- **Dependencies:** frontmatter library, vector store
- **Size target:** 220 lines (currently 174 lines)

### Module: `templates/index.html`
- **Responsibility:** Single-page UI for ingest, keywords, discovery.
- **Interface:** Browser DOM + htmx/vanilla JS
- **Dependencies:** Backend API endpoints
- **Size target:** 1200 lines (currently 1032 lines)

### Module: `core/discovery_scheduler.py`
- **Responsibility:** Background keyword search + ingestion. Never creates new keywords.
- **Interface:** `start()`, `stop()`, `add_keyword()`, `remove_keyword()`, `get_keywords()`, `trigger_cycle()`
- **Dependencies:** pipeline, vector_store, interest_domain_matcher
- **Size target:** 770 lines (currently 767 lines)

## Error Handling

- **Preview fails (fetch error, LLM error):** Return 502 with error message. UI shows error in progress card. User can retry.
- **Phase 2 fails mid-pipeline:** SSE stream shows error. Keywords already added to `_keywords` are NOT rolled back (they're valid topics, just the pipeline failed). User can retry ingest.
- **New keyword already exists (race):** `add_keyword` raises ValueError. Caught in Phase 2, skipped silently. Note is still saved with the keyword in its frontmatter.
- **Discovery trigger while scheduler disabled:** Return 400 with "Discovery is disabled".
